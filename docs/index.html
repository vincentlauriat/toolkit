PluginsPlugins外掛

Two plugins, for now.Deux plugins, pour l'instant.目前有兩個外掛。

  • /audit-report

    Generate exhaustive audit dossiers on any company, product, technology, or market — like a strategy consulting firm.Générez des dossiers d'audit exhaustifs sur n'importe quelle entreprise, produit, technologie ou marché — comme un cabinet de conseil en stratégie.針對任何公司、產品、技術或市場，產出詳盡的稽核檔案——就像一家策略顧問公司。

    --depth quick|full · --lang en|fr · --mode parallel|sequential|solo · --swot · --esg · --rh · --brief · --watch · --app-mode

    audit-report homepagePage d'accueil d'audit-reportaudit-report 首頁

  • /marcel

    Marcel — frame an app before coding: a new idea (greenfield) or an existing codebase (brownfield), as a one-page overview plus six consistent documents written in docs/specs/.Marcel — cadrer une app avant de coder : une idée neuve (greenfield) ou un code existant (brownfield), en une présentation d'une page et six documents cohérents écrits dans docs/specs/.Marcel——寫程式之前先框定 App：全新構想或既有程式碼，在 docs/specs/ 中產出一頁總覽與六份彼此一致的文件。

    Greenfield starts with a short interview (four rounds, multiple-choice where possible). Brownfield reads the code first, documents what is there with the file each fact comes from, and turns the plan into an evolution plan. Existing specs are updated in place.Le greenfield commence par un court entretien (quatre tours, à choix multiples quand c'est possible). Le brownfield lit d'abord le code, documente ce qui existe en citant le fichier de chaque fait, et fait du plan un plan d'évolution. Les specs existantes sont mises à jour sur place.全新專案從一段簡短訪談開始（四輪，盡可能採用選擇題）。既有專案則先讀程式碼，記錄現有內容並註明每項事實的來源檔案，並把計畫改為演進計畫。既有規格會就地更新。

What an audit containsCe que contient un audit一份稽核包含什麼

Up to 10 Markdown sections, plus machine-readable artifacts.Jusqu'à 10 sections Markdown, plus des artefacts lisibles par machine.最多 10 個 Markdown 章節，外加機器可讀的產出物。

Each run produces a structured audit-{subject}/ folder. The optional dimensions (ESG, SWOT, HR) are only generated when you ask for them.Chaque exécution produit un dossier structuré audit-{subject}/. Les dimensions optionnelles (ESG, SWOT, RH) ne sont générées que si vous les demandez.每次執行都會產生一個結構化的 audit-{subject}/ 資料夾。選用面向（ESG、SWOT、人資）只有在你要求時才會產生。

  1. HistoryHistorique歷史

  2. MarketMarché市場

  3. TechnicalTechnique技術

  4. PricingTarification定價

  5. CompetitionConcurrence競爭

  6. FinancialsFinances財務

  7. Future outlookPerspectives未來展望

  8. ESG

  9. SWOT

  10. HRRH人資

Alongside the Markdown: _data.json · _sources.json · _manifest.json — so the dossier stays machine-readable.À côté du Markdown : _data.json · _sources.json · _manifest.json — pour que le dossier reste lisible par machine.Markdown 之外還有：_data.json · _sources.json · _manifest.json——讓檔案保持機器可讀。

What the specs containCe que contiennent les specs規格文件包含什麼

An overview plus six documents, checked before the skill reports done.Une présentation et six documents, vérifiés avant que la skill annonce avoir fini.一份總覽加上六份文件，在技能回報完成前先經過檢查。

  1. Overview — project presentation and document map, written lastPrésentation — le projet et la carte des documents, écrite en dernier總覽——專案介紹與文件地圖，最後撰寫

  2. PRD — features, success metric, risksPRD — fonctionnalités, indicateur de succès, risquesPRD——功能、成功指標、風險

  3. TRD — technical choices, tests, run costTRD — choix techniques, tests, coût d'exploitationTRD——技術選擇、測試、營運成本

  4. User flows — every screen, path and stateParcours utilisateur — chaque écran, chemin et état使用者流程——每個畫面、路徑與狀態

  5. Design brief — visual direction and UX rulesBrief de design — direction visuelle et règles UX設計簡報——視覺方向與 UX 規則

  6. Data model — data, relations, access rulesModèle de données — données, relations, règles d'accès資料模型——資料、關聯、存取規則

  7. Implementation plan — build order, effort, traceabilityPlan d'implémentation — ordre de construction, effort, traçabilité實作計畫——建置順序、工作量、可追溯性

  • Three modesTrois modes三種模式

    New app — greenfield (interview, then the seven documents) · existing project — brownfield (reads the code first, documents what is there, plans only the gap) · update (edits existing specs in place and logs the revision).Nouvelle app — greenfield (entretien, puis les sept documents) · projet existant — brownfield (lit d'abord le code, documente ce qui existe, ne planifie que l'écart) · mise à jour (modifie les specs existantes sur place et consigne la révision).新 App——全新專案（先訪談，再產出七份文件）· 既有專案（先讀程式碼，記錄現有內容，只規劃差距）· 更新（就地編輯既有規格並記錄修訂）。

  • CheckedVérifié經過檢查

    Unknown answers become flagged assumptions collected in the PRD's open questions; a traceability table links every priority feature to its screens, entities and tasks, and is checked by a shipped script (check.py, with a self-test that proves it catches failures).Les réponses inconnues deviennent des hypothèses signalées, regroupées dans les questions ouvertes du PRD ; une table de traçabilité relie chaque fonctionnalité prioritaire à ses écrans, entités et tâches, et un script fourni la vérifie (check.py, avec un autotest qui prouve qu'il détecte les erreurs).未知的答案會成為標記的假設，彙整於 PRD 的待決問題；一張可追溯性表將每個優先功能連結到其畫面、實體與任務，並由隨附的腳本檢查（check.py，附自我測試以證明它能抓出錯誤）。

  • RequiresPrérequis需求

    python3 for the checker. Optional: mmdc (mermaid-cli) to render the Mermaid diagrams.python3 pour le script de contrôle. En option : mmdc (mermaid-cli) pour dessiner les diagrammes Mermaid.檢查腳本需要 python3。選用：mmdc（mermaid-cli）以繪製 Mermaid 圖表。
